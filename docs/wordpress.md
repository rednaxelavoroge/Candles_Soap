# Перенос на WordPress

Этот репозиторий — прототип на Next.js: эталон дизайна, структуры и поведения.
Боевой сайт заказчица просила на WordPress, чтобы править контент самой.
Здесь описано, что переносится как есть, что придётся собирать заново и
где лежат данные для импорта.

## Модель контента → сущности WordPress

Схема из `src/data/schemas.ts` ложится на WordPress без натяжек.

| Здесь | В WordPress |
| --- | --- |
| товар (`products.json`) | Custom Post Type `product` |
| категория (`candles`, `soap`, …) | таксономия `product_category`, иерархическая |
| теги повода (`wedding`, `new-year`, …) | таксономия `occasion`, плоская |
| теги адресата (`men`, `kids`, …) | таксономия `recipient`, плоская |
| теги формы (`geometric`, …) | таксономия `form`, плоская |
| `images[]` | галерея вложений у записи |
| `video` | одно поле с ссылкой на YouTube или Vimeo |
| `price`, `specs{}` | пользовательские поля (ACF или родные custom fields) |

Три таксономии вместо одной — принципиально. Именно они дают фильтры «повод +
адресат + форма» и заменяют плоский список из 38 разделов: внутри группы теги
складываются по «или», между группами — по «и». Сводить их в одну таксономию
нельзя: фильтры сломаются, а список разделов заказчицы перестанет раскладываться.

`form` пока состоит из одного тега `geometric` («Свечи геометрической формы»),
но это отдельная ось, а не подвид повода.

## Данные для импорта

`src/data/products.json` — готовый источник: 15 товаров с названиями,
описаниями, категориями, тегами и путями к обработанным изображениям.
Загружается скриптом через WP-CLI или REST API, руками перебивать не нужно.

Изображения в `public/catalog/` уже приведены к 1600px и WebP. WordPress
сгенерирует из них свои размеры сам, повторная обработка не требуется.

⚠️ Цены и характеристики в `products.json` предварительные и придуманы
разработчиком — см. README. Импортировать их в боевой сайт нельзя, пока
заказчица не подтвердит каждую строку.

## Видео

В WordPress ссылка на YouTube или Vimeo, вставленная отдельной строкой,
разворачивается в плеер автоматически (oEmbed) — заказчица сможет добавлять
ролики сама, без разработчика.

Заливать видеофайлы в медиатеку не нужно и вредно: они занимают место на
хостинге, отдаются медленно и не адаптируются под скорость соединения.

## Что переносится тяжело

- **Секция split-scroll.** Расходящиеся половины завязаны на прогресс скролла
  (`useScroll` + `useTransform`). В теме WordPress это переписывается на
  IntersectionObserver и CSS-трансформы либо на GSAP ScrollTrigger. Логика
  описана в `src/components/home/SplitReveal.tsx` — переносить нужно смысл,
  а не код.
- **Дизайн-система.** Палитра, шрифты и правила сетки лежат в
  `src/app/globals.css` в виде токенов. В теме их повторить несложно, но
  собирать через визуальный конструктор не стоит: белая рамка между
  изображениями, отсутствие теней и скруглений быстро расползаются.
- **Скорость.** Прототип статический, Lighthouse на мобиле 97 на главной.
  WordPress с плагинами это не повторит; закладывайте кеширование и
  отключение лишнего.

## Что переносится легко

Тексты, структура страниц, разбивка кадров по товарам (`tools/photo-plan.json`),
обработанные изображения, модель категорий и тегов, JSON-LD и OpenGraph
(закрываются любым SEO-плагином).
